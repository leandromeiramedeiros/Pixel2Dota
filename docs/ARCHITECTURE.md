# Architecture — core concepts and contracts

5v5 Dota on the real Dota 2 map. Authoritative Colyseus server (30 Hz sim), Three.js voxel client rendered into a low-res pixel target. Custom lobby + match only.
The code is the source of truth; every module's header comment is its contract. This file holds only what you need to know before touching
anything. To add a hero / item / spell fx / quality setting, see [EXTENDING.md](EXTENDING.md).

## Coordinates and scale
- Sim/world: Dota units, x east, y north, map box [-8832, 8832]. Ground z from `shared/map.js heightAt(x, y)` (elevation tier x 128, ramps interpolate).
- Three.js: `X = x`, `Y = z` (up), `Z = -y`. 1 Three unit = 1 Dota unit. Every fx/wind/geo3d API takes WORLD coords and converts internally.
- Pixel density: 6 Dota units per art pixel (`ART_UNITS_PER_PX`). A 48u tile = 8x8 px. Voxels: characters 4.2 u, world 8.4 u (exactly 2:1).
- Tiles: 368x368 of 48u, row 0 = north. `type` 0 grass, 1 tree, 2 cliff, 4 road, 5 water, 6 outside; `elev` 0 river / 1 lanes / 2 high ground; `ramp` flag.

## Camera (`shared/constants.js CAMERA`, `render/camera.js`)
- Yaw is 0 (looking north) everywhere except the showcase; there the player orbits the hero. Default distance 1134, pitch 60 deg, horizontal FOV 70 at 4:3 (vertical ~55.4 deg, constant across aspects).
- Zoom: 1134 (desktop max) -> closeDistance 900 (pitch 38, fov 45) -> showcase 800 (pitch 14, fov 50, eye ~260u up = tree-canopy height, looking at the hero's chest, hero ~1/4 of the screen) -> dolly to showcaseMin 480. Showcase = `distanceGoal < closeDistance`; the director keeps the hero centred, DoF ramps to full.
- Orbit (showcase only, `rig.orbit(dYaw, dPitch)`): yaw free, pitch `orbitPitchMin..Max` (5..60); yaw eases back to 0 (shortest way) once out of the showcase. Eye = look + d (sin yaw cos pitch, sin pitch, cos yaw cos pitch). Desktop: middle-drag, Alt + left-drag or left-drag on empty ground (a click still deselects), wheel zooms, edge pan off. Touch: `ui/orbit.js` (attaches to the canvas, capture phase): one-finger drag rotates, pinch zooms, left joystick zone and taps untouched.
- Anything that depends on the view direction uses the camera matrices or `rig.yaw` (picking / `worldToScreen` / rangefinder do): sprite frame = `dirOf(viewFacing(facing, yaw))`, key-light rim direction rotates with yaw, clutter cull box is symmetric while `yaw != 0`. Don't hard-code "screen up = north" in render code.
- Touch: max and starting distance 1450 (`ui/touch.js T.ZOOM_FAR/ZOOM_START`), pinch in only. Sprites always scale with perspective (`spritePersp: 1`).
- `renderer.setViewInset({top, bottom})` frames the target in the part of the screen the HUD leaves free (touch); the DoF focus band follows.
- **Director** (`render/camdir.js`, pure, node-tested; `renderer.cam`): the ONE owner of where the camera looks. Writers send intents (`pan`, `jumpTo`,
  `centre`, `setFollow`, `holdFollow`, `suspend`, `peekStart/Move/End`, `aimAt`); game.js calls `renderer.stepCamera(dt, {hero, moveDir})` once a frame
  (interpolated hero + alive, touch joystick), which places the rig (`rig.place`, no rig lerp). `renderer.setTarget/snapTarget` = a user jump (legacy;
  sandbox.js / fxdemo.js still drive the rig directly). Tunables: `CAMERA_FEEL`.
  - Modes: follow | free | peek (touch look-around over the base mode) | orbit (showcase: hero centred; pan / peek / jumps ignored).
  - Player moves (pan, edge / arrows with `edgeRamp`, middle-drag, minimap, centre, peek drag) are instant. Automatic moves (follow, return to follow,
    peek spring-back, aim lean) use a critically damped spring (`smoothDamp`, exact, frame-rate independent).
  - Follow anchor = hero + lead (velocity x `leadTau` + joystick, capped `leadCap` x visible height) + aim lean (capped) + the spring's lag, so the
    camera never trails a moving hero. Follow error > `cutVH` visible heights (TP, long blink, respawn, far return) = a cut (`snap`: ground height snaps too).
  - Never moves on its own otherwise: no auto-zoom, nothing on kills; follow pauses while the hero is dead, cuts to it on respawn.
  - Any user pan / jump while following drops to free (Dota); `suspend` = temporary free that keeps the lock (touch minimap press, aim edge pan).

## Network
- Server authoritative, no client prediction. Sim 30 Hz fixed step (own accumulator in MatchRoom). Patches flushed manually once per tick (`setPatchRate(null)`).
- Room `"match"`, `roomId` = 4-letter code. 10 player seats + `SPEC_MAX` 6 spectator seats (host toggle). Bots fill empty seats.
- Rejoin: `allowReconnection` 60 s; after that a returning client reclaims its seat by stored seat id or unique name (`Player.claim`, `MatchRoom.seatFor`);
  the client boot auto-rejoins the last live match (`net/index.js` SEAT_KEY / LAST_KEY). One controller per hero: the old session is sent away.
- Spectator POV (`shared/pov.js`, `client/src/pov.js`, `ui/spectate.js`): spectators default to free roam; "Player perspective" follows one seat. Players send throttled `MSG.POV` (camera x/y/distance, selection, aim); the room validates (`cleanPov`, `createPovGate`), relays to spectator seats only, and also relays every sim-accepted order (humans and bots, `World.onOrder`). Bots fall back to following their hero. The fog checkbox picks that team's fog (`fog.reset()` per vision key) or full reveal.
- Interpolation: `net/clock.js` stamps each patch with server sim time mapped onto `performance.now()`; render delay adapts to measured jitter
  between 70 and 350 ms (`DELAY_MIN/MAX`). Jumps > 450 u between samples are teleports (no lerp).
- VFX, projectiles, damage numbers, chat are **events**: the room broadcasts `"fx"` once per tick with an array of `{e: EV.*, ...}` objects.
  Constructors and payloads: `server/src/sim/events.js`. Spells: `evSpell(w, key, srcId, {t,x,y,x2,y2,r,dur,lv,sub})`; `sub` = sub-event of a cast (never gusts).

### Schema (`server/src/room/schema.js`, source of truth)
`MatchState { phase, code, time, night, winner, spectators, players: Map<Player>, units: Map<Unit>, vision: Map<VisionSrc>, treesDown: [uint16] }`.
`Unit` = `id` + the `UNIT_FIELDS` list in schema.js (position, anim, hp/mana, status bits, hero stats) + `abilities: [Ability{key, level, cd, cdMax, mana, flags}]`, `items: [Item{key, charges, cd, cdMax}]` (9 slots: 6 main + 3 backpack, `INV_SLOTS`/`ACTIVE_SLOTS`), `buffs: ["key:secondsLeft"]`.
`Player { sid, name, team, slot, hero, isBot, isHost, connected, claim, heroId, gold, kills, deaths, assists, lh, dn }`. `VisionSrc { id, team, x, y, r }`.
The sim keeps plain objects with the same field names; MatchRoom copies the `*_FIELDS` lists each tick. Add a synced field = schema + field list + sim object.

### Messages (`shared/protocol.js`)
- Client -> server: `lobby {t: LOBBY.*}`, `order {t: ORDER.*, ...args, q?}` (`move attack amove stop hold cast item learn buy sell swap`, `q` = shift-queue), `chat {text}`.
- Server -> client: state patches + `fx` events (EV: `atk hit spell proj projEnd death kill gold lvl heal mana tree treeGrow blink tp invoke msg chat end`).

## Simulation (`server/src/sim`, API in [API.md](../server/src/sim/API.md))
`World` owns units, players, clock, events. Modules: `world` (loop/spawns/win), `units` (factories from DATA), `nav` (A* on 48u tiles), `move`, `combat`
(attack cycle, armor/MR, crit/cleave hooks), `status` (modifiers + status bitmask), `heroes` (attributes, XP, gold, respawn), `creeps`, `buildings` (tier
protection, ancient win), `neutrals` (camps + Roshan), `wards`, `vision` (temporary team vision sources), `items`, `abilities/` (registry), `bots`, `orders` (cast flow).
Rules: `shared/constants.js`; numbers: DATA — never hard-code what the bake provides. Randomness: `w.rand()` only (seeded, deterministic).

## Data flow
```
game files --bake--> shared/data/*.js --> sim (numbers)        sim plain objects --MatchRoom--> schema patches --> net view (interpolated) --> renderer / HUD
                                     \-> HUD tooltips, shop     sim events (w.emit) --"fx" broadcast--> render/fx handlers, HUD feed, wind gusts
```
Fog of war is client-side (server sends everything); `state.vision` carries temporary sources (spell vision). Tooltips/shop/icons are keyed by ability/item key.

## Render systems (rules and limits for anyone adding to them)
- **Pipeline** (`render/post.js`): scene into a low-res HalfFloat target (`pixelScale` rows per art pixel; nearest) -> tilt-shift DoF blur -> bloom
  (threshold 1.4, progressive mips) -> water SSR -> final pass (adaptive exposure, hue-preserving roll-off, light-scatter halo, grade, atmospheric
  perspective, vignette, nearest upscale). DoF strength follows the camera distance (`camera.js dofForDistance`): `DOF_MIN` 0.12 at play distance, ramping
  to 1 from closeDistance down to the showcase close-up. Fight whiteouts are prevented by exposure + roll-off; keep lights hue-local rather than raising intensity.
- **Showcase atmosphere** (`post.js`, ramped by `camera.js showcaseK` = `uSky`; while `state.sky <= SKY_MIN` the normal FINAL program runs, the showcase code is compiled out via `#ifdef SHOWCASE`; tier = quality key `atmos` 0..3): two passes at scene-RT resolution, composited by FINAL. ATMOS: undrawn pixels get a day/night gradient, sun/moon disc at the key azimuth, night stars and (tier 1+) raymarched slab clouds; drawn pixels get distance fog (`fogRange()`, pulled in by a short `drawDist`) plus a raymarched ground mist (10 / 22 / 32 steps + key-light scatter); output rgb = added light, a = kept scene (sky flagged negative). SDOF: bokeh DoF (focus = camera distance, hero sharp; 8 / 16 / 24 taps), only when the `dof` option is on; it gathers the keep-premultiplied scene and, in a second pass with the same taps (ATMB), the ATMOS light, so FINAL composites a blurred atmosphere (a sharp sky / fog composite would re-cut every far silhouette).
- **Terrain** = a 3D heightfield with cliff walls (`terrain.js`, `terrainGeo.js`), shaded as voxel ground (`VOXT` mode, `VOX_CELL` 8.4, materials in
  `shared/vox/terrain.js`); voxel tufts in `clutter3d.js`. **Buildings, trees, clutter** are 3D instanced meshes (`buildings3d.js`, `trees3d.js`,
  `clutter3d.js`), being converted to voxel (VOXEL.md "Conversion order"). Lighting is 9-level Bayer-quantised (`shaderlib.js LIGHT_LEVELS`) on terrain and meshes;
  geo3d fx and beams use stepped bands, never ordered dither.
- **Voxel units** (`voxmesh.js`, `voxactors.js`): one compact geometry per pose frame (12 B / vertex: Int8 position + face byte, Int8 smooth normal +
  hash, Uint8 colour + emit gain), built lazily on a hero's first `add()`, drawn instanced. The vertex shader leans each body 30 deg about its feet away
  from the camera (in the shadow pass too), pushes an inverted-hull outline, and breaks the model into falling voxels on death (heroes ragdoll 2 s first: `ragdoll.js`, per-segment transforms in the `uRag` texture; VOXEL.md). Emissive tiers: eye <= 1,
  signature ~1.2, spell 1.5-1.7. Until sprite removal (batch 7) units still sort at foot depth.
- **Ground fx must be geo3d discs/quads at `heightAt`**, never billboards drawn below a unit's foot. Legacy sprites (`sprites.js`, retiring in batch 7) sort
  each pixel at its true height above the foot.
- **Lights** (`lights.js`, `shadow.js`): pool of `MAX_LIGHTS` 32 per frame, selected by intensity x radius, distance-weighted (`selectLights`). The `MAX_PS` 10 strongest spell lights get real
  cube shadows (atlas row per light); the rest fall back to marched height-field shadows + one-bounce fill. Sun/moon key light casts near-overhead shadows.
  Rule: only spells and items cast big lights; basic attacks, towers and creeps stay under the bloom threshold (`fx/projectiles.js ATK_LIGHT` 0.3).
- **Spell fx** (`render/fx/`): router `fx/index.js` -> `fx/<short>.js register(c, R)`. Particles (`particles.js`, GPU instanced, HDR colours bloom) +
  `geo3d.js` pooled 3D geometry (tube / disc / bolt, immediate mode inside `c.run`) + `quads.js` + `beams.js`. Ring telegraphs: `c.ringDecal(x, y, R, dur,
  tint, o)` = geo3d TARGET disc + coloured ground light (`grow` is a radius multiplier, `light: false` skips the light). Never stretch `decal_ring_target`.
- **Spell vision**: `w.addVision()` in the sim (`vision.js`) -> `state.vision` -> client `fog.js` casts from each source like a friendly unit.
- **Spell wind** (`wind.js`): up to `MAX_GUSTS` 8 gusts derived from EV.SPELL events (shape swirl/line/burst from targeting, strength from damage, size
  from radius/range, read generically from DATA; `OVERRIDES` per key). Trees + clutter shaders read the shared gust uniforms: plants bend away from the spell (burst outward, swirl spirals out, line along the cast) and hold a rocking lean for ~3-6 s. Pull spells (`OVERRIDES.pull`: hook, dismember, mana drain, spell steal, berserker's call; EMP pulls while charging then bursts via `then`) flip the field inward. Death debris and hero ragdoll launches (`launchAt`) read the same gusts. Attacks never gust.
- **Quality** (`quality.js`): *Level* low / medium / high / ultra = a *preset* (renderer `settings` for fidelity: `bloomStrength/Levels, shadows, shadowPoints, maxLights,
  particles, ambient, clutter, rim, wind, ssr, rays, atmos, drawDist, msaa, outlines`; `ultra` must equal `render/index.js DEFAULTS`, tested; graded low <= ... <= ultra) plus an *option bundle*
  (`LEVEL_OPTIONS`: resolution 1/4, 1/2, native -> `pixelScale` 1, sqrt2, 2; fps cap 30/60/120/144/165/MAX (0 = display refresh); `bloom`; `dof`; vsync). Picking a level applies both and
  forgets manual option overrides; an option changed afterwards is stored (`p2d.gfx.opts`) and wins. Targets: low = potato 30 fps 1/4, medium 60 fps 1/2, high 60 fps native + bloom,
  ultra native refresh + 2x MSAA + DoF. `detectDefaults(info)` (pure; GPU string, cores, memory, screen, phone, refresh) picks one of four tiers (potato / low-mid / good / ultra).
  `drawDist` = how far trees (near cells first), clutter and the showcase far plane reach; terrain chunks also build in the background so a camera swing never waits.
  `loop.js` runs the frame: rAF + `createFrameCap` accumulator, or timer/MessageChannel when vsync is off. Quality is decided once at load; nothing lowers it during a match.
- **World UI in the showcase**: hp bars and combat text fade out where the showcase fog starts and behind the camera (`uiFade` in `render/index.js`), and bars are size-capped.
- **Fog** (`fog.js`): tile-resolution vision grid, Dota rules (three levels river < lane < high ground: rays blocked by higher ground and live trees, a higher level sees down, `state.vision` sources are flying unless `ground`); radius from DATA (hero visionDay/visionNight, unit `vision`, night mirrors the sim). Three looks: visible / fogged (explored) / never seen (`FOG_UNSEEN_DARKEN`, 0 = pure Dota); soft eased edge; enemy structures stay drawn as last seen (`fog.ghost`).
- **Input**: `input.js` (desktop, header lists every key). `ui/touch.js`: joystick, attack button (tap / drag-to-target with hero priority), last-hit button,
  and the wheel: spell arc (`arcLayout`) + an outer arc of up to 6 small item slots (`smallArcLayout`) holding only usable (non-passive) main items,
  packed, in a per-hero order by inventory slot (`p2d.wheelItems.<hero>` v2; new items append). No item row, no hotkey letters. A BAG button left of
  the attack button opens a popover of all 9 slots (6 main + 3 backpack): drag cell -> cell = `ORDER.SWAP`, cell -> small slot = wheel order, tap =
  tooltip + SELL in shop range (desktop rule); tap outside / BAG closes. Spells: tap / double-tap self-cast / drag-to-aim with rangefinder (clipped at
  the camera near plane). The icon never moves; the knob shows the cursor. Spell aim (`aimCursor`) starts at the hero's preview point; a comfortable
  thumb reach (`AIM_REACH_X/Y` x screen, scaled by sensitivity 0.75..2.5, default 1.5) sweeps it to the screen edge, where it edge-pans, so one thumb
  covers the whole screen. Attack drag / pad radius `AIM_R / s`. The move joystick stays live (multi-touch). Cancel: release over the CANCEL X above the wheel, or slide
  back onto the button. Holding a spell/item still 0.75 s shows its tooltip (release does not cast); 1.75 s enters wheel reorder (spells and small
  items, per hero). HUD bottom bar, left to right: minimap, hero portrait, stats (desktop), bars/items;
  portrait: tap/double tap/click centres the camera, press-and-hold 0.5 s shows the full stats panel (`format.heroStats`) while held. Pinch zoom, menu button.
  Desktop camera: Y lock, F1 centre, hold Space = follow while held, edge / arrows / middle-drag pan (drops the lock), an armed cast leans the view.
  Touch camera: locked by default (CAM toggles), led by the joystick; locked one-finger press (`classifyPress`): tap = move (enemy = attack), hold still
  = keep moving to the finger, quick deliberate drag = peek (springs back). The minimap sits top-left under the top bar (left thumb reach, clear of the
  joystick); pressing it suspends the lock to cast far with the right thumb, release / cast end returns. The aim cursor of a long-range spell at a
  screen edge pans fast (`edgePanDir`), only once it has left the pressed button or the drag passes 0.2 of the radius (`edgePanArmed`); spell aim
  leans the view.
  Pure helpers (`holdPhase`, `releaseAction`, `aimCancelled`, `portraitPhase`, `edgePanDir`, `edgePanArmed`, `packWheelItems`, `dropAction`) in
  `ui/touch.js` / `ui/targeting.js` are node-tested.
- **Order paths** (`ui/orderpath.js`, drawn by hud.js): every move / attack / attack-move order (desktop and touch, not the joystick) shows marching dashes
  along the A* path from `shared/nav.js` (the same nav the server sim walks) with a cross at the end; green move, red attack, orange attack-move; 1 s fade.
